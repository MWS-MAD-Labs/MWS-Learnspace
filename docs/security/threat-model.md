# Learnspace authorization and privacy threat model

## Review status

This is a living engineering threat model for P7-008, based on repository controls as of 2026-09-02. It is **not** an external security assessment, privacy impact approval, penetration test, or owner sign-off. The owners named below are functional roles and remain `TBD` until assigned. Open and accepted risks are tracked in [`risk-register.md`](risk-register.md); no risk is accepted merely because it is documented.

## Scope, assets, and trust boundaries

Assets include student identity/contact data, educational records, disability/special-education records, IEPs, observations, reports, staff identities and assignments, organization membership, OAuth/session material, audit events, exports/imports, backups, logs, and encryption identities.

Trust boundaries:

1. untrusted browser and public network → same-origin ingress/web proxy;
2. ingress/web → API security boundary;
3. API → PostgreSQL system of record;
4. API → Google OpenID Connect;
5. deployment/scheduler operators → secrets, database, logs, and encrypted backups;
6. backup storage → authorized restore host/key custodian.

The browser, request identifiers, organization IDs, roles, workflow states, export contents, and operator-provided files are untrusted until server-side validation and authorization. PostgreSQL, deployment controls, Google, host storage, and operators are privileged dependencies, not automatically trustworthy.

## Abuse cases reviewers must exercise

- Modify browser requests to substitute another `organizationId`, actor, role, student, assignment, workflow state, or version.
- Reuse/replay OAuth state, callback code, session cookie, CSRF token, approval command, import, and export request.
- Use disabled, expired, unassigned, cross-tenant, and least-privileged memberships against every protected route.
- Attempt broad list/search/report/export access where only assigned-student or subject scope is allowed.
- Attempt to inject sensitive values into logs/audit metadata and spreadsheet/export cells.
- Interrupt encryption, publication, decryption, restore, verification, and cleanup; confirm no plaintext or disposable database remains.
- Simulate lost/unavailable backup identity, wrong recipient, missing sidecar, stale backup, and cleanup failure.

## Security review gate

P7-008 should not be treated as complete until named owners:

1. map every protected endpoint and bulk data path to the authorization matrix and negative tests;
2. review OAuth/session configuration and secret rotation in the deployed environment;
3. review exports/imports, backups, logs, and audit storage against an approved data classification/retention policy;
4. disposition every high/critical risk in the risk register with mitigation evidence or explicit authorized acceptance and expiry;
5. record the reviewer, date, scope, findings, and follow-ups in a separate dated review record.
